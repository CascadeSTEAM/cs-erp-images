## Summary

Scoped and began executing a full theming overhaul of the Cascade STEAM Builder site. Found
the real style guide — the legacy Quartz site's own `quartz.config.ts` plus a 669-line
`custom.scss` that turns out to be an undocumented component library — wrote two design specs,
then applied design tokens and published a component library to the live site. Along the way
uncovered two serious pre-existing defects the site had been silently living with. Steps 0–2
of the build order are complete and live; steps 3–4 were in flight at session end.

## Decisions Made

- **Layout comes from the CURRENT site, not the legacy one.** The first draft anchored the
  component inventory on Quartz's `custom.scss` — the layout being replaced. Owner corrected
  this. Sources are now split by concern: layout from the live site, brand/palette/fonts from
  the Quartz config, interaction vocabulary from `custom.scss`, old-site chrome not ported.
- **Accent-only orange** — a state, not a surface. Cyan stays structural.
- **Dark tokens minted, light-only implementation.** No `prefers-color-scheme` branches.
- **Token strategy: rename/remap in place, not full reset.** The full-reset call rested on the
  13 pages being throwaway; once the owner clarified the layout is the reference
  implementation, that premise was wrong.
- **One `Website Entry` doctype** with an `entry_type` selector, so creators learn one form.
  Core `Event` + Custom Fields for events; ERPNext becomes canonical, Google Calendar retired.
- **Banner fields collapsed six → one.** 31 of 37 legacy pages used the identical logo and
  nobody ever varied the positioning.
- **`new.` is not public**, so visible breakage is fine and the owner prefers watching changes
  land over having them staged behind safe no-ops.

## The Costly Near-Miss

An instruction to swap the new `cs_header_v2`/`cs_footer_v2` blocks into the live components
**would have destroyed the header and footer on all 13 pages.** Pages don't embed component
content — they hold empty override shells keyed by `referenceBlockId`, and `extend_block()`
builds children from those shells by matching `blockId`. A freshly-composed tree matches
nothing, collapsing every interior node to `element=None`, with no `sync_component()` to
repair it. Caught by simulating before writing. Documented in `tools/cs-website/README.md`.
